# T014 — Vulkan Functional Verification on Steam Deck

## Status: RESOLVED — verified working on Deck (2026-09-20)

Empirical result on Steam Deck (RADV VANGOGH, API 1.4.330, Mesa 26.0-devel):
all 3 acceptances pass. `VulkanEngine` now does full GPU inference with
`gpu == cpu_reference` to float32 precision across `ones`, `hot0`, and `cold`
inputs (see `aes/tickets/T014-verify.md`).

## Confirmed root causes (all fixed)

### RC-1 — `VkPhysicalDeviceMemoryProperties` layout wrong [fixed]
Engine used 264 B struct; real layout is 520 B → stack overflow clipped the
`VkDescriptorSetAllocateInfo` chain, so `vkAllocateDescriptorSets` read garbage
`descriptorPool` and `pSetLayouts` and segfaulted inside `vkUpdateDescriptorSets`.
Fixed to real ABI (32×VkMemoryType + 16×VkMemoryHeap, 520 B).

### RC-2 — ctypes handle assignment pitfall [fixed]
`writes[i].dstSet` now uses `.value`, not the ctypes object.

### RC-3 — wrong `VK_DESCRIPTOR_TYPE_STORAGE_BUFFER` value [NEW, fixed]
Engine used `5`; canonical value is **`7`** (`VK_DESCRIPTOR_TYPE_STORAGE_TEXEL_BUFFER=5`).
RADV treated the descriptor as a texel buffer → dereferenced NULL
`pTexelBufferView` and SIGSEGV at `mov (%rax,%r12,8),%rax` (r12=0). This was the
**original** segfault (line 752/767). Confirmed with a standalone C ABI
reproducer: crash at `vkUpdateDescriptorSets` with `descriptorType=5`, clean with `7`.

### RC-4 — wrong `VkStructureType` sType constants [NEW, fixed]
All `VK_STRUCTURE_TYPE_*` constants were guessed (e.g. `MEMORY_BARRIER=4` =
`SUBMIT_INFO`). Synced to canonical `vulkan_core.h` values (WRITE_DESCRIPTOR_SET=35,
MEMORY_BARRIER=46, COMMAND_BUFFER_BEGIN_INFO=42, etc.).

### RC-5 — stale read-back in multi-pass compute [NEW, fixed]
Single command buffer with `hidden`+`output` passes returned results lagging one
input behind: pass 2 read stale `hidden`. The in-cmd-buffer `vkCmdPipelineBarrier`
did **not** order pass 2 after pass 1 on this RADV build (verified: two separate
submissions with a fence between passes → always correct). `compute()` now submits
per pass with an explicit fence wait between them.

### RC-6 — `vkCmdBindDescriptorSets` argtypes mismatch [NEW, fixed]
Argtypes list had one extra `c_uint32` → `TypeError: takes at least 9 arguments`.
Corrected to the real 8-parameter signature.

## Acceptance criteria — all met

- **AC-1** ✅ `VulkanEngine.initialize()` completes without crash on Steam Deck.
- **AC-2** ✅ `compute()` returns logits matching CPU reference (maxerr ~1e-7)
  for ones / hot0 / cold inputs.
- **AC-3** ✅ `make test` (92 passed, 1 skipped), `make lint` clean locally.
- **AC-4** ✅ Proof test run on Deck recorded — `aes/tickets/T014-verify.md`.

## Critical finding for ops

The Deck's RADV dev build (Mesa 26.0-devel, `vulkan-radeon 26.0.0_devel`) does not
honour an intra-command-buffer `vkCmdPipelineBarrier` between two compute passes on
the same buffer, but **is** fully correct when ordering is established via separate
queue submissions + fence. Engine now uses the submission-boundary approach —
correct today, and the more defensive pattern in general.
